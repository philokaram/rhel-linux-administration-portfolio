# Working with systemd-journald — Notes

## 1. What Is the Journal?

- **systemd-journald** = systemd's logging service (part of systemd)
- Creates an **indexed database** of logging events below `/run/log/journal/`
- Collects logs from: kernel, boot output, services, syslog

### Volatile storage:

```
/run/log/journal/
```

- Contents deleted on reboot (recreated by tmpfiles framework)
- Query interface: **`journalctl`**

---

## 2. Why Journalctl?

### Traditional log files:

- Need awkward **regular expressions** to extract specific data
- Difficult to filter by time, user, priority, etc.

### Journal:

- **Structured** and **indexed**
- Easy to filter by:
  - Time (`--since`, `--until`)
  - Priority (`-p`)
  - Unit (`-u`)
  - User (`_UID`)
  - Executable (`_EXE`)
  - Boot (`-b`)

> 💡 **Key benefit:** Much easier to query than traditional log files.

---

## 3. Basic journalctl Commands

### View entire journal (oldest first):

```bash
journalctl
```

### View most recent messages first (reverse):

```bash
journalctl -r
```

### View last N lines:

```bash
journalctl -n 20
```

### Follow live updates (like `tail -f`):

```bash
journalctl -f
```

> 💡 Use `Ctrl+C` to stop following.

---

## 4. Filtering by Priority — `-p`

### Show messages with priority **warning** and higher:

```bash
journalctl -p warning
```

### Priority colors:

| Priority | Color |
|----------|-------|
| Warning | Yellow |
| Error, Crit, Alert, Emerg | Red |

### Priority levels:

| Priority | Option |
|----------|--------|
| `emerg` | `-p emerg` |
| `alert` | `-p alert` |
| `crit` | `-p crit` |
| `err` | `-p err` |
| `warning` | `-p warning` |
| `notice` | `-p notice` |
| `info` | `-p info` |
| `debug` | `-p debug` |

> 💡 Priorities are **cumulative** — `-p warning` includes `warning`, `err`, `crit`, `alert`, and `emerg`.

---

## 5. Filtering by Time — `--since` and `--until`

### Since a specific date/time:

```bash
journalctl --since "2025-08-31 00:00:00"
```

### Between two dates:

```bash
journalctl --since "2025-08-31" --until "2025-09-01"
```

### Relative time:

```bash
journalctl --since "6 hours ago"
journalctl --since "yesterday"
journalctl --since "1 hour ago"
```

---

## 6. Filtering by Systemd Unit — `-u`

### Show logs for a specific unit:

```bash
journalctl -u sshd.service
```

> 💡 The `-u` option shows **messages generated by AND about** the unit (other daemons may mention it).

### Combine with priority:

```bash
journalctl -u insights-client.service -p err
```

---

## 7. Filtering by Boot — `-b`

### Show logs from current boot:

```bash
journalctl -b
```

### Show logs from previous boot:

```bash
journalctl -b -1
```

### List all boots:

```bash
journalctl --list-boots
```

> 💡 Requires persistent journal storage (`Storage=persistent` in `/etc/systemd/journald.conf`).

---

## 8. Filtering by Executable — `_EXE`

### Show logs from a specific binary:

```bash
journalctl _EXE=/usr/bin/sudo
```

---

## 9. Filtering by User — `_UID`

### Show logs for a specific user:

```bash
journalctl _UID=$(id -u student)
```

Or:

```bash
journalctl _UID=1000
```

---

## 10. Combining Filters — Granular Queries

### Example — errors about `insights-client` since a specific date:

```bash
journalctl -u insights-client.service -p err --since "2025-08-31"
```

# Journalctl — Common Options Summary

| Option | Meaning | Use Case |
|--------|---------|----------|
| `-r` | Reverse order (newest first) | Quick view of recent events |
| `-n N` | Show N lines | Limit output |
| `-f` | Follow (live updates) | Real-time monitoring |
| `-p` | Priority filter | Show only warnings/errors |
| `--since` | Start time | Troubleshooting specific timeframe |
| `--until` | End time | Troubleshooting specific timeframe |
| `-u` | Systemd unit | Service-specific logs |
| `-b` | Current boot | Boot-time issues |
| `-b -1` | Previous boot | Issues from last boot |
| `_EXE` | Executable path | Logs from a specific program |
| `_UID` | User ID | Logs from a specific user |

# Journal vs Traditional Logs — Comparison

| Feature | Journal (journalctl) | Traditional Logs (/var/log/) |
|---------|---------------------|------------------------------|
| Structure | Indexed database | Plain text files |
| Query by time | Easy (`--since`, `--until`) | Complex (grep regex) |
| Query by priority | Easy (`-p`) | Complex (grep) |
| Query by unit | Easy (`-u`) | Complex |
| Query by user | Easy (`_UID`) | Very complex |
| Persistence | Volatile (by default) | Persistent |
| Performance | Fast queries | Slower (file scans) |

---

# Key Takeaways

- **Journal** = systemd's logging service (`systemd-journald`).
- **Storage:** `/run/log/journal/` (volatile by default).
- **Query tool:** `journalctl`.
- **Priorities:** `emerg`, `alert`, `crit`, `err`, `warning`, `notice`, `info`, `debug`.
- **Filter by priority** with `-p` (e.g., `-p warning` includes warning + higher).
- **Filter by time** with `--since` and `--until`.
- **Filter by unit** with `-u` (shows messages by AND about the unit).
- **Filter by boot** with `-b` (current), `-b -1` (previous).
- **Filter by executable** with `_EXE=/path/to/binary`.
- **Filter by user** with `_UID=1000`.
- **Follow live** with `-f` (like `tail -f`).
- **Reverse order** with `-r` (newest first).
- **The journal is much easier to query** than traditional log files — no complex regular expressions needed.
