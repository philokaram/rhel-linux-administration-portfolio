# Configuring Hostnames and Name Resolution — Notes

## 1. Viewing Hostname Information

### Short hostname (from prompt):

```bash
hostname
```

### Full hostname details:

```bash
hostnamectl
```

**Output example:**
```
   Static hostname: serverb.lab.example.com
   Transient hostname: serverb
         Icon name: computer-vm
           Chassis: vm
        Machine ID: abc123...
           Boot ID: def456...
    Virtualization: kvm
  Operating System: Red Hat Enterprise Linux 10
       CPE OS Name: cpe:/o:redhat:enterprise_linux:10
            Kernel: Linux 6.1.0-0.el10.x86_64
      Architecture: x86-64
```

### Hostname types:

| Type | Meaning |
|------|---------|
| **Static hostname** | Permanently set (stored in `/etc/hostname`) |
| **Transient hostname** | Dynamically determined (reverse DNS lookup of IP) |

### Where static hostname is stored:

```bash
cat /etc/hostname
```

---

## 2. Changing Hostname — The Right Way

### Use `hostnamectl` (persistent):

```bash
hostnamectl hostname api.datacenter.example.com
```

### Verify:

```bash
hostname
hostnamectl
```

### Why not just `hostname` command?

| Method | Persistent? | Updates `/etc/hostname`? |
|--------|-------------|---------------------------|
| `hostname newname` | ❌ No (lost on reboot) | ❌ No |
| `hostnamectl hostname newname` | ✅ Yes | ✅ Yes |

### Updating the prompt:

- The prompt may not update immediately
- Start a new shell or **log out and back in** to see the change

> 💡 The most reliable way: log out completely, then log back in.

## 3. Name Resolution — Overview

Two main sources for name resolution:

| Source | Scope | File/Service |
|--------|-------|--------------|
| **Local file** | Per-system | `/etc/hosts` |
| **DNS** | Centralized | DNS servers (in `/etc/resolv.conf`) |

---

## 4. Testing Name Resolution — Commands

### Simple test (ping):

```bash
ping -c1 www.redhat.com
```

### System resolution (uses nsswitch order):

```bash
getent hosts www.redhat.com
```

### Simple DNS lookup:

```bash
host www.redhat.com
```

### Powerful DNS lookup — `dig`:

**A record (IPv4 address):**

```bash
dig www.redhat.com
```

or explicitly:

```bash
dig in a www.redhat.com
```

**MX record (mail exchange):**

```bash
dig in mx redhat.com
```

**Reverse DNS (IP to name):**

```bash
dig -x 1.1.1.1
```

### What `dig` shows:

- **QUESTION SECTION:** What was asked
- **ANSWER SECTION:** The resolution result (may include CNAME aliases)
- **Server:** Which DNS server answered the query

## 5. Managing DNS Settings — `nmcli`

### View DNS servers for a profile:

```bash
nmcli con show datacenter | grep ipv4.dns
```

### View all DNS configuration:

```bash
cat /etc/resolv.conf
```

**Example output:**
```
search lab.example.com example.com
nameserver 192.168.0.220
nameserver 1.1.1.1
```

| Directive | Meaning |
|-----------|---------|
| `search` | Domains to append to short names |
| `nameserver` | DNS server IP addresses |

## 6. Local Name Resolution — `/etc/hosts`

### Format:

```
IP_address    name1 name2 name3...
```

### Example:

```bash
cat /etc/hosts
```

```
127.0.0.1   localhost localhost.localdomain
::1         localhost localhost.localdomain
172.25.254.254 classroom.example.com classroom
```

### Characteristics:

- **Local to each system** (must be managed per system)
- **Not centralized** — doesn't scale
- Takes precedence over DNS (by default)

---

## 7. Resolution Order — `/etc/nsswitch.conf`

This file controls the **order** of name resolution sources.

### Key line:

```bash
grep ^hosts /etc/nsswitch.conf
```

**Typical output:**
```
hosts: files dns myhostname
```

### Order meaning:

| Source | Meaning |
|--------|---------|
| `files` | Check `/etc/hosts` first |
| `dns` | Then query DNS |
| `myhostname` | Finally, check if name matches this system's hostname |

> 💡 The order is **left to right** — first match wins.

### Changing the order:

To make **DNS authoritative** (check DNS first):

```
hosts: dns files myhostname
```

### ⚠️ Warning:

```
# This file is generated by authselect. Do not edit manually.
# Instead, use the authselect tool.
```

> 📌 Managing `nsswitch.conf` manually is not recommended. Use `authselect` (beyond scope of this course).

# Name Resolution Flow

```
Application requests "www.example.com"
              │
              ▼
         /etc/nsswitch.conf
              │
              ├── files → /etc/hosts
              │              │
              │              ├── Found? → Return IP
              │              └── Not found? → Continue
              │
              ├── dns → /etc/resolv.conf
              │              │
              │              ├── Query DNS server
              │              ├── Found? → Return IP
              │              └── Not found? → Continue
              │
              └── myhostname → Check if name matches local hostname
                                   │
                                   ├── Found? → Return IP
                                   └── Not found? → Resolution fails
```

# Key Takeaways

- **`hostnamectl`** = the right way to set hostname persistently (updates `/etc/hostname`).
- The `hostname` command alone makes **temporary** changes (lost on reboot).
- **Transient hostname** comes from reverse DNS lookup of the system's IP.
- Name resolution order is defined in `/etc/nsswitch.conf` (default: `files dns myhostname`).
- **`/etc/hosts`** = local, per-system resolution (takes precedence over DNS by default).
- **`/etc/resolv.conf`** = DNS server configuration (managed by NetworkManager).
- **`dig`** = the most powerful DNS lookup tool (A records, MX records, reverse DNS).
- **`getent hosts`** respects the nsswitch order (files → DNS → myhostname).
- **`/etc/nsswitch.conf`** is managed by `authselect` — do not edit manually.
- To make DNS authoritative, change the order in `nsswitch.conf` to `dns files myhostname`.
